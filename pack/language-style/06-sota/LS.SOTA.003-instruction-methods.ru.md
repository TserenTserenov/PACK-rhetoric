# [LS.SOTA.003] Методы написания пошаговых инструкций

> Обзор для жанра «пошаговая инструкция для человека» (`overlays/genre/instruction.yaml`, слот LS.FORM.012). Каждый источник закрывает конкретное правило жанра. Источники сверены 11.11.2026 по официальным страницам и вторичным обзорам; где сверка шла только по вторичным, это сказано.

## Что берём из каждого метода

| Метод | Правило жанра | Как сверено |
|---|---|---|
| Минимализм Кэрролла (J. M. Carroll, *The Nurnberg Funnel*, 1990; H. van der Meij, J. M. Carroll, «Principles and heuristics for designing minimalist instruction», *Technical Communication* 42(2), 1995) | Сразу к действию; помощь при ошибке (заметить, понять, исправить) стоит там, где ошибка случается, сразу после шага | Вторичные обзоры (instructionaldesign.org, EduTech Wiki, van der Meij & Lazonder 1993); первоисточник не открывали |
| Структура задачи DITA 1.3 (OASIS) | Порядок разделов: что нужно заранее (prereq) → контекст → шаги → результат → устранение сбоев (tasktroubleshooting) → пример → что дальше (postreq); все разделы необязательны | Спецификация OASIS DITA 1.3, «task elements» |
| ASD-STE100, упрощённый технический английский | Одна инструкция в предложении; процедурное предложение не длиннее 20 слов (описательное — 25); предупреждение начинается с команды и стоит до действия | Вторичные обзоры; официальный текст выпуска 9 платный, не открывали. Порог 20 слов написан для английского, на русском — рекомендация до калибровки |
| Google developer documentation style guide, раздел «Procedures» | Один шаг — одно действие; мелкие действия по меню — в одном шаге через «>»; место действия называется до действия; если у шага есть цель, цель называется до действия | Официальная страница developers.google.com/style/procedures |
| Microsoft Writing Style Guide, «Procedures and instructions» | Не перегружать шагами, вся процедура в идеале помещается на один экран; короткие действия в одном и том же месте интерфейса можно объединить в один шаг; где начинать — фразой о месте, затем глагол в повелительном наклонении; при риске путаницы — вводный шаг | Официальные страницы learn.microsoft.com/style-guide/procedures-instructions и чек-лист (сверены проверяющим 11.11.2026, обновление страниц 15.10.2026) |
| Microsoft Manual of Style (прежнее печатное издание) | Не больше 7 шагов, лучше меньше | Вторичные обзоры; в действующем онлайн-руководстве Microsoft числа нет, там «на один экран» |
| ISO 24495-1:2023, ясный язык | Четыре принципа: читатель получает нужное, находит, понимает и может использовать; успех меряется тем, может ли читатель применить текст, а не формулой читаемости | Обзоры IPLF и iiiD; основной текст стандарта платный |

## Что из этого следует для IWE

- Базовое правило для любого агента (где нажать, как открыть программу в первый раз, одна команда в одной рамке, глагол перед командой, что человек увидит, проверка глазами новичка) уже принято автором 11.11.2026 и живёт в DP.SC.050. Методы выше его не заменяют, а добавляют строение инструкции и пороги.
- Принцип ISO о том, что успех меряется применением, — основание для слепого и практического теста (РП-619 Ф5): инструкция хороша, если новичок прошёл её без вопросов, а не если она прошла скрипт.
- При конфликте с голосом автора: понятность новичку > проверяемость шага > ритм голоса (решение пир-сессии 11.11.2026).
