# Реестр языковых стилей — операционные правила

> see DP.SC.173 (реестр), DP.SC.174 (диспетчер), DP.SC.175 (выбор пользователя).
> Архитектура: `compiler.py` (ключ → фрагмент промпта), `dispatcher.py` (событие → ключ),
> `style_selector.py` (выбор пользователя → user_override), `style_metrics.py` (метрики).

## Слот ≠ Overlay (наложение) — операционное правило

**Слот** (`05-formalizations/LS.FORM.NNN`) — регистр: параметр ВЫБОРА по композитному ключу
`(reader_meta_class, reader_role, channel, domain)`. Один ключ → один слот (или fallback).

**Overlay** (`overlays/{domain,market,genre,author}/`) — правка ПОВЕРХ уже выбранного слота,
слой каскада `base → domain → market → genre → author → user`. Не выбирается ключом целиком —
накладывается по условию применимости (`applies_to`, `market=`, `domain=`).

**Тест:** «это параметр выбора (кто читатель / какой канал → какой регистр) или правка поверх
выбранного (сегмент аудитории, структура жанра, авторский слой)?» Выбор → слот. Правка → overlay.

Примеры (peer-сессия 2026-06-12-02):
- ЦА «системные мыслители» — overlay (тон-пресет сегмента), НЕ отдельный слот: втиснуть ЦА в слот =
  размножение регистров на каждый сегмент.
- `channel=telegram` — параметр ключа (рантайм-факт интерфейса), НЕ overlay.

Hot-различения дисциплины (Поле ≠ Отношение ≠ Канал; Голос ≠ Тон) — в `~/IWE/.claude/rules/distinctions.md`;
полный distinction-set Ф1 (7 различений) — в контракте пака (`01-domain-contract/`).

## Классы источников манифеста (registry-manifest.lock)

| Префикс id | Что | Участвует в компиляции |
|------------|-----|------------------------|
| `slot:` | регистры LS.FORM.* | да (выбор по ключу) |
| `content:` | владельцы контента L0/L1 (content-sources.yaml) | да (материализация) |
| `overlay:<класс>:` | наложения каскада | да (правки поверх) |
| `extra:` | presets.yaml, genre-template/* | **нет** — только freshness-сигнал verify |

`extra:` — namespace в манифесте, не отдельный класс логики: правка этих файлов меняет
manifest_hash → verify сигналит, derived-кэш инвалидируется. Чтением presets владеет
`style_selector.py` (единственная точка чтения); манифест — точка наблюдения.

## Perf: повторное хэширование при compile (решение 2026-06-12)

`compute_manifest()` на каждый compile_key хэширует ~25 файлов из 3 репо — миллисекунды,
вызов не в hot-path (старт сессии / правка файла). Оптимизация (кэш хэшей) ОТКЛОНЕНА как
преждевременная. Возврат к вопросу по любому из триггеров:
(а) >200 файлов в манифесте; (б) lock/verify >100 мс на типовом сетапе;
(в) диспетчер попадает в per-message hook.
