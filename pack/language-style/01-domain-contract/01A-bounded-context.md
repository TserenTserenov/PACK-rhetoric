# Граница домена: Языковые стили

## Ядро домена

**Языковой стиль** в контексте этого Pack = функциональная настройка высказывания под ситуацию коммуникации, отделённая от предметного содержания. Не «красиво писать» — а **выбрать правильное отношение к читателю и форму под канал**, наложив их на лексику домена в момент ответа.

Ядро дисциплины — **две оси Холлидея (отношение + канал) плюс голос**. Это ситуативно-независимая основа (фундаментальный стиль, аналог FPF). Поле (третья ось) сюда НЕ входит — оно отделено founding axiom теории регистра.

## Что входит в ядро (дисциплина владеет)

- **Ось отношения (tenor)** — двухуровневая: мета-класс читателя (человек / агент) + роль (пилот / новичок / ученик / напарник / исполнитель / разработчик).
- **Ось канала (mode)** — как роль языка зависит от носителя (письменный/устный, плотность). Внимание: дисциплина описывает влияние канала на стиль, но НЕ выбирает канал.
- **Голос** — стабильная подпись агента, ортогональная регистру.
- **Тон** — ситуативная настройка поверх голоса (формальность, юмор, уважительность, энтузиазм).
- **Регистр** (производное) — поле×отношение×канал под ситуацию.
- **Жанр** (примитив второго порядка) — конвенция целого текста.
- **Наложения** — доменное (профиль поля) и рыночное (сегмент аудитории) как кросс-осевой слой каскада.

## Что НЕ входит в домен

- **Поле (field)** — предметная лексика. Живёт в доменном паке и графе понятий WP-415. Дисциплина композирует с полем, не владеет им.
- **Выбор канала** — какой именно мессенджер/интерфейс активен. Рантайм-факт интерфейса IWE. Дисциплина даёт лишь канально-условные правки стиля.
- **Содержание предметных понятий** — это объясняемое знание, не способ его подачи.

## Расширение оси отношения: человек / агент / код

Дисциплина одна, регистры разные по типу читателя:

| Читатель | Мета-класс | Регистр |
|----------|-----------|---------|
| Пилот, новичок, ученик, аудитория | человек | разговорный, бытовой, академический, ЦА |
| Напарник, исполнитель | агент | плотный технический, контракт задачи |
| Разработчик (через код) | человек/агент | инженерный (отношение разработчик × канал код) |

**«Код» — это канал (mode), а не третий тип читателя.** Читатель кода — человек-разработчик или парсящий агент. Инженерный регистр = `отношение: разработчик × канал: код`.

## Граница с содержащимся паком rhetoric

`rhetoric` (RHE) описывает риторические приёмы (тропы, фигуры, иллюстрации) — строительный материал убеждения внутри высказывания. `language-style` (LS) описывает функциональную настройку высказывания целиком. Риторика — раздел дисциплины, её приёмы применяются внутри выбранного регистра.

## Связь с архитектурой IWE (WP-392 «Суть ≠ Интерфейс»)

Поле и ядро отношения/голоса держит платформа (единый источник). Канал адаптирует интерфейс. Инвариант: один вопрос через любой интерфейс → один по сути ответ, меняется только канал.
