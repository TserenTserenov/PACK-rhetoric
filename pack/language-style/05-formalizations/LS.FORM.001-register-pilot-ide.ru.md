# [LS.FORM.001] Регистр пилота в IDE (разговорный)

> **Эталонный пример регистра** для контракта интерфейса дисциплины (WP-412 Ф4а → WP-415 Фаза Б). Демонстрирует паттерн «регистр = слот + ключ контекста + указатель на владельца контента».

## Что это

Регистр для ответа агента пилоту в среде разработки (IDE): режим «на пальцах», русский язык, активный залог, без машинных маркеров.

## Ключ контекста (стык с реестром DP.SC.173)

```yaml
context_key:
  reader_meta_class: human   # мета-класс читателя
  reader_role: pilot         # роль выбирает регистр
  channel: ide               # канал (рантайм-факт от интерфейса)
  domain: "*"                # домен неважен для этого регистра
```

Полный ключ реестра достраивается в момент lookup: `(context_key, user_override_hash, platform_layer_hash)`. Отпечаток платформенного слоя считает реестр из активных наложений; диспетчер передаёт только плоские факты (см. DP.SC.173, DP.ROLE.073/074).

## Контент (проекция, не копия)

Правила этого регистра — A1-A11 разговорного стиля. **Источник истины — DP.SC.050** (`communication-style-base.md` L0 + авторский L1). Реестр при компиляции тянет фрагмент из владельца контента, этот файл его не дублирует.

Краткая суть регистра (для ориентира, НЕ источник):
- Главная мысль в первых двух предложениях; ЧТО до КАК.
- Английский термин и код — только после русского описания в скобках.
- Путь к файлу — не подлежащее.
- Активный залог на ошибках и находках; никаких машинных маркеров (готово вместо exit 0).
- До 7 пунктов, один экран, 2-3 предложения в абзаце.

## Голос

Голос агента (LS.D.002) накладывается поверх этого регистра, узнаваем и стабилен. Регистр задаёт ситуативную рамку, голос — подпись.
