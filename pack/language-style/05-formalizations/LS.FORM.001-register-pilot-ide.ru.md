# [LS.FORM.001] Регистр пилота в IDE (разговорный)

> **Эталонный пример регистра** для контракта интерфейса дисциплины (WP-412 Ф4а → WP-415 Фаза Б). Демонстрирует паттерн «регистр = слот + ключ контекста + указатель на владельца контента».

## Что это

Регистр для ответа агента пилоту в среде разработки (IDE): режим «на пальцах», русский язык, активный залог, без машинных маркеров.

## Ключ контекста (стык с реестром DP.SC.173)

```yaml
context_key:
  reader_meta_class: human   # мета-класс читателя
  reader_role: pilot         # роль выбирает регистр
  channel: ide               # канал (рантайм-факт от интерфейса)
  domain: "*"                # домен неважен для этого регистра
```

Полный ключ реестра достраивается в момент lookup: `(context_key, user_override_hash, platform_layer_hash)`. Отпечаток платформенного слоя считает реестр из активных наложений; диспетчер передаёт только плоские факты (см. DP.SC.173, DP.ROLE.073/074).

## Контент (проекция, не копия)

Правила этого регистра — свёрнутая 5-форма правил A1-A11. **Источник истины — DP.SC.050**, раздел «5 правил разговорного регистра (агент → пилот)» в `communication-style-base.md` (L0); полная детализация A1-A11 — в авторском слое L1. Реестр при компиляции тянет фрагмент из владельца контента, этот файл его не дублирует.

5-форма канона (зеркало L0-раздела, не отдельный источник):
1. Читатель - пилот, не инспектор: эффект до того, как сделано; лишнее под спойлер. (A4, A5, A7, A8)
2. Английский - только после русского описания в скобках; голые маркеры (exit 0, PASS, SHA) запрещены. (A2, A3, A10)
3. Путь к файлу - не подлежащее. (A1)
4. Активный залог на ошибках и находках. (A11)
5. Детектор канала: стенограммы/commit/PR - плотно, чат с пилотом и синтез отчёта - «на пальцах». (A9)

> **Свёртка 11→5 (WP-388 Ф4):** 5-форма выведена из 11 правил A1-A11 (исследование 8 источников: HumanLayer, Anthropic Engineering, IFScale). Канон закреплён в L0, переживает смену автора/L1.
