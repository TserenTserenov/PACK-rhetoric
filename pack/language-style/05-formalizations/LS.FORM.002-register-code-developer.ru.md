# [LS.FORM.002] Регистр разработчика (инженерный код)

> **Второй эталонный регистр** для контракта интерфейса (WP-412 Ф5, MVP компилятора). Демонстрирует каскад на разнице с разговорным регистром: разные владельцы контента (`DP.SC.172` vs `DP.SC.050`), разный канал, разное поведение наложений.

## Что это

Регистр для написания и правки кода: запахи P0-P5, инженерный craft-уровень. Отношение «автор → будущий читатель кода» × канал «код». Грамотное программирование как коммуникация.

## Ключ контекста (стык с реестром DP.SC.173)

```yaml
context_key:
  reader_meta_class: human   # человек-разработчик под мета-классом «человек»
  reader_role: developer     # роль выбирает регистр
  channel: code              # «код» — это канал (mode), не третий тип читателя
  domain: "*"                # P0-P5 язык-агностичны; язык-уникальные запахи → overlays/domain
```

## Контент (проекция, не копия)

Правила — P0-P5 инженерного стиля. **Источник истины — DP.SC.172** (`engineering-code-style-base.md` L0). Реестр при компиляции тянет фрагмент из владельца, этот файл не дублирует.

Краткая суть (для ориентира, НЕ источник):
- P0 — форматтер+линтер репо перед коммитом.
- P1 — тест без проверки наблюдаемого результата запрещён.
- P2 — третье повторение → функция.
- P3 — мёртвую ветку удалять, не «для совместимости».
- P4 — `except: pass` без логирования запрещён.
- P5 — длинную функцию со смешанными обязанностями разбить.

## Граница с разговорным регистром

Разговорный (LS.FORM.001) и инженерный (этот) — две разные точки оси отношения × канала. Доменное наложение `overlays/domain/` добавляет язык-уникальные запахи (Rust borrow и т.п.) к инженерному, но не трогает разговорный. Это и проверяет MVP-каскад Ф5.
