# [RHE.SC.001] Поиск иллюстраций в библиотеке риторики

## Правило (инвариант)

- Возвращаемые иллюстрации **сохраняют структурные отношения** целевого концепта —
  не просто «похожи» поверхностно.
- Иллюстрации **не противоречат друг другу** в пределах одного Pack'а и одной программы.
- Контрпримеры возвращаются **только** если `audience_level ≥ 3` (запрошен) или явно указан
  фильтр `effect: counter`.
- При пустом результате — возвращается промпт для создания новой карточки по
  шаблону `templates/illustration-card.md`.

## Обещание

**Кому:** автор руководства, поста, презентации, или агент (Навигатор R27).

**Зачем:** без библиотеки авторы изобретают аналогии заново при каждом тексте, получают
несогласованность («Болид» в одном руководстве, «автомобиль» в другом для того же концепта).
Библиотека гарантирует: если аналогия уже найдена — она переиспользуется и остаётся согласованной
во всей программе.

**Вход:**

| Параметр | Тип | Обязательный | Описание |
|----------|-----|-------------|----------|
| `concept_id` | string | ✅ | ID концепта из Pack: `PD.D.042` |
| `pack_ref` | string | ✅ | Pack, где живёт концепт: `PACK-personal` |
| `audience_level` | 1-5 | — | Уровень читателя; default: 2 |
| `effect` | enum | — | `explain` / `persuade` / `inspire`; default: `explain` |
| `trope_type` | enum | — | Фильтр по типу: `analogy`, `case`, `metaphor`... |
| `max_results` | int | — | Максимум карточек; default: 3 |

**Выход:**

Список карточек иллюстраций, отсортированный:
1. по `canonical: true` (первыми)
2. по соответствию `audience_level` (ближайшие к запрошенному)
3. по `quality_score` (descending)

Каждая карточка включает: `id`, `trope_type`, `source_text`, `structural_core`, `breaks_when`.

**Время отклика:** синхронно (lookup в файловой системе Pack'а или индексе).

**Режим отказа:** нет карточек по запросу → пустой список + ссылка на шаблон
`templates/illustration-card.md` с инструкцией «создай и внеси вклад».

## Что НЕ делает этот сервис

- Не создаёт новые иллюстрации (это R15 M-RM, отдельный SC в PACK-digital-platform)
- Не оценивает качество запрошенного концепта
- Не изменяет карточки (read-only)

## Концепция использования (сценарии)

### Сценарий A — Автор пишет раздел руководства

| # | Шаг | Кто |
|---|-----|-----|
| 1 | Автор пишет раздел про «Созидатель» (PD.D.042) | Автор |
| 2 | Запрашивает: `concept_id=PD.D.042, pack_ref=PACK-personal, effect=explain, audience_level=2` | Автор → RHE.SC.001 |
| 3 | Получает 3 карточки: Болид (analogy, canonical), Асептика (analogy), Земмельвейс (case) | RHE.SC.001 |
| 4 | Выбирает Болид для текста; Земмельвейс — для доп. аргумента | Автор |

### Сценарий B — Навигатор объясняет концепт студенту

| # | Шаг | Кто |
|---|-----|-----|
| 1 | Студент (ст. 2, background = физика) спрашивает «что такое Созидатель?» | Студент |
| 2 | Навигатор R27 знает `cp.skl=2`, background=физика → запрос с `audience_level=2` | Навигатор |
| 3 | Получает Болид (source_domain=sport, level=2) + Паровой каток (source_domain=tech, level=2) | RHE.SC.001 |
| 4 | Выбирает Болид как более знакомый для audience; объясняет через него | Навигатор |

### Сценарий C — Новый концепт, иллюстраций нет

| # | Шаг | Кто |
|---|-----|-----|
| 1 | Автор запрашивает иллюстрации для нового концепта из PACK-MIM | Автор |
| 2 | Результат пустой | RHE.SC.001 |
| 3 | Возвращает: «Иллюстраций для этого концепта нет. Создай карточку по шаблону...» | RHE.SC.001 |
| 4 | Автор создаёт карточку в процессе написания, добавляет в `illustrations/` | Автор |

### Сценарий D — Ночной mining (R15 M-RM)

| # | Шаг | Кто |
|---|-----|-----|
| 1 | R15 обрабатывает пост клуба с высоким resonance | R15 (M-RM mode) |
| 2 | Извлекает структурные аналогии, создаёт черновые карточки | R15 |
| 3 | Карточки попадают в `illustrations/pending/` со статусом `draft` | R15 |
| 4 | RHE.SC.001 не возвращает `draft` карточки до верификации | Инвариант SC |
| 5 | Верификатор (R23 или автор) проверяет, ставит `quality_score`, меняет статус `active` | Верификатор |
