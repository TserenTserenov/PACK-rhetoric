# [RHE.METHOD.009] Ценность до механики

## Суть метода

Структурировать любое представление (онбординг, описание инструмента, первый слайд, руководство) в порядке «зачем» → «что»: сначала ценность/эффект для пользователя, потом функциональное описание.

Обратный порядок («что→зачем») ставит механику раньше, чем пользователь понял, нужно ли ему это — результат: высокий cognitive overhead и churn на первом экране.

## Алгоритм применения

1. Сформулировать ответ на вопрос: «Что изменится в жизни пользователя, когда он это освоит?» (ценность/эффект).
2. Поставить этот ответ первым предложением.
3. Только после — описать, что именно делает инструмент/продукт/раздел.
4. Тест: «Первое предложение отвечает на "зачем мне это?"» Да → ОК. Нет → переставить.

## Когда применять

- Онбординг продукта: первый экран, первое письмо
- Описание инструмента или функции (docs, README-intro)
- Первые слайды презентации
- Вводные разделы руководств участника программы

## Когда НЕ применять

- Техническая документация (аудитория уже решила «зачем» и ищет «как»)
- Описание для экспертов того же домена (peer context: «зачем» очевидно)
